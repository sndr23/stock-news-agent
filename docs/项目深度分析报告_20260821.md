## 一、项目定位与架构总览

这是一套**多源聚合 + 事件驱动 + LLM 严格判定 + 微信实时推送**的 A 股重大资讯监测系统，并逐步演进出**量化因子采集**与**中信期货持仓日报**两条并行能力线。

核心价值主张（README）：*重大消息立刻推到微信，日常流水静默丢弃，财联社式体验*。

### 全景架构

```
┌─ 实时资讯线：data_fetchers(8新闻源+2信号源) → 三层去重 → 事件指纹(48h)
│            → 规则预筛(≥0.55) → LLM 6档判定 → 强档门槛 → 同事件合并 → 跨轮拦截 → 微信推送
├─ 量化因子线：factor_collector(P0-P12，8源HTTP轮询) → 方向合成(IC加权) → 异动推送/简报
├─ 中信持仓线：query/push_citic_futures_pos（中金所XML，IF/IH/IC/IM全合约聚合）
└─ 信号回测线：signal_backtest（pushed_events → 后1/3/5日收益一致性 + 分层IC）
        │
        └─ 状态层：GitHub Gist(云端) + logs/(本地)，读-改-写合并
        └─ 调度层：5 个 GitHub Actions workflow
```

### 生产入口与调度（共 4 个运行脚本 + 1 个本地辅助）

| 入口脚本 | 对应 workflow | 触发策略 | 是否用 LLM |
|---|---|---|---|
| `real_time_push.py` | realtime-push（资讯）+ market-brief（盘前/盘后） | 云端 realtime 由 cron-job.org 分时段 POST（盘中15min/美股30min/其余60min，约46次/日）；brief 用 GitHub 原生 cron `45 0`(08:45) / `10 7`(15:10) | 资讯线用；brief 不用 |

| `daily-review/build_report.py` | **无 workflow，本地手工** | — | 不用 |

## 二、实时推送生产管线（核心）

`scripts/real_time_push.py` 遵循清晰流水线：抓取 → 去重 → 指纹 → 预筛 → LLM 判定 → 合并 → 推送 → 状态。运行模式：单次（云端）/ `--loop`（本地常驻，`RT_POLL_SECONDS` 默认120s）/ `--dry-run`（诊断）/ `--brief`。

### 数据抓取层（data_fetchers.py）
- **8 个新闻源**：东财快讯、财联社电报（直连API）、新浪、同花顺、富途全球、华尔街见闻（直连）、金十数据（直连）、Google News RSS。**2 个信号源**：龙虎榜（机构净买入≥3000万）、业绩预告（幅度>100% 或 <-50%）。
- **并行抓取**：`ThreadPoolExecutor`，`as_completed(timeout=120)` + 每源 30s 超时，**失败源隔离返回空**。长挂源（akshare）使用 (connect, read) 元组超时。
- **三层去重**：URL 规范化 → 标题精确 → SimHash 近似（3-gram/32位/汉明≤3判重）。⚠️ SimHash 为 O(n²) 两两比较。
- **沪深300缓存**：进程单例 → 本地文件（48h TTL）→ akshare 实时，三级降级。

### LLM 判定层
- **预筛**：`calculate_prefilter_importance` 多因子叠加 + Sigmoid；门槛 `PREFILTER_SCORE_MIN=0.55`；宏观数据/大额经营/科技龙头直通。
- **6 档方向**：bullish/mildly_bullish/neutral/mixed/mildly_bearish/bearish。
- **批处理**：LLM_BATCH_SIZE=8，MAX_CANDIDATES_PER_ROUND=40；`_call_llm_api(timeout=60, max_retries=1, deadline=300)`。
- **idx 对齐防漏推**：注入 `_judge_idx` 要求回显，`by_idx` 精确对齐 + `by_title` 兜底，未对齐 → **挂起下轮重试，绝不静默判 false**。
- **300s 总超时熔断**：批次入口检查 + **批次完成后复查**（防单批 182s 突破预算）。
- **候选溢出挂起**：>40 时核心/宏观/普通分级优先，普通条目连续 3 轮仍溢出则放弃；**高信号条目永不放弃**。

### 去重与指纹（本项目最强项）
- **事件级指纹**（48h）：高信号词/事件组/金额 → `date|sig|ev|st` 结构化；普通流水 → 标题归一化；md5 64bit。L306 掺入标题主语片段修复"寒武纪 vs 宁德时代回购5亿胶原码碰撞漏推"。
- **推送级事件签名** `_is_same_event`（约160行，12 个合并分支）：实体别名归一（大摩=摩根士丹利）、板块子串包含、LCS 连续子串 + 子序列双实现、方向守卫（涨vs跌、鹰vs鸽）。含大量实证修复背书（恩智浦/索尼台积电/日本央行/纳指三推）。
- **跨轮同事件拦截** + **同题材饱和**（板块/实体 24h 已推≥5 不再推，market 级豁免）。
- **同事件合并完成后置**：5a 事件签名分组 → 5b 选最优代表 → 5c 门槛/噪声/科技兜底/拦截/格式化。

### 推送后端（push.py）
- PushPlus / 企业微信 / WxPusher 三实现，指数退避 2s/4s，确定性错误码不重试，UTF-8 字节截断（企微 3800 字节）。
- **红涨绿跌**：A 股惯例 + emoji 表达方向。
- ⚠️ **WxPusher 已实现但未接入生产主流程**，属死代码路径。

### 状态持久化（Gist）
- 读带 `?ts=` 时间戳绕 CDN，3 次重试读不到 → fail-stop（P0 修复）；缺 `seen` 键视为损坏拒绝空状态。
- 写整文件 PATCH，读-改-写 **merge**（seen 并集、pushed=True 优先、索引去重），滚动清理控制体积 <1MB。

## 三、评分 / 因子 / 持仓子系统

### 预筛重要度（calculators.py）
四支并行：噪音(0.10) / signal(龙虎榜幅度bonus) / announcement(5级分级表，ST退市降级) / news(类别+政策+科技+板块叠加，tanh压缩)；涉及个股但非科技/非豁免源再 ×0.65 降权。

### 因子体系（factor_collector.py，P0–P12）
- **P0-P11 分层**：对冲/风险/量价/汇率/波动率/宽度为正式 6 维；流动性/期权情绪/韩指(KOSPI)/日线/分钟为**影子维度**。
- **机构式因子上线流程**：影子维度先记录进 direction_history 供 IC 回测，IC 达标才升级正式维度。
- **数据源**：免费 HTTP 主动轮询，UA 轮换池 + 东财多主机 fallback + 三冗余（新浪→腾讯→东财日K）。
- **方向合成**：6 维 IC 加权 `Σ(w×s)/Σw`，P5-1 门控（高波×1.5/普跌+日元急升×1.5），P5-2 确信度分层（≥0.67 单独推，0.5-0.67 进简报）。

### 信号回测（signal_backtest.py）
读 pushed_events → 后 1/3/5 日收益一致性，按 scope/方向/板块分组；`compute_factor_ic`（Spearman，自实现无 scipy）；`compute_layer_ic`（P11 分层单调性）；`compute_winrate`。样本<10 不计比率，冷启动明确标注。

### 中信期货持仓（query/push_citic_futures_pos.py）
- 中金所 ccpm XML，datatypeid 0/1/2 = 成交量/持买单/持卖单。
- **全合约聚合**：IF/IH/IC/IM 各品种所有挂牌合约加总，`net = buy − sell`，跨品种求和（符合项目硬约束口径）。
- 交易日判断用 `chinese_calendar.is_workday`（ImportError 降级 weekday<5）；Gist 去重 `last_pushed_day` 每交易日只推一次；`--force` 绕过，`--dry-run` 只打印。

## 七、总体评价

**成熟度显著高于一般个人量化项目**。三大亮点：

1. **实证驱动的根因修复文化**：每个阈值/词表/修复点后都附着具体交易日实例与根因（8-13 日元套息、8-12 美国 CPI 漏推、nAMD/STorage 误命中、纳指三推），"基金会归因"工程素养在训练数据中罕见。
2. **模块解耦与单一事实来源**：LLM 客户端已从废弃 nodes.py 抽到 `llm_client.py`（纯 httpx），`keyword_tables.py` 收敛词表，共享层（push/data_fetchers/calculators/llm_client/config/schemas）被 scripts 干净复用。
3. **机构式因子上线流程**：影子因子 → IC 回测 → 达标升级正式维度；多层 JSON 容错 + 截断逐对象恢复 LLM 解析 —— 全链条可靠性设计到位。

**核心短板**集中在三处：**Gist 并发一致性**（非原子读改写）、**`_is_same_event` 复杂度过大**造成的回归风险、以及**历史废弃 `src/agent` 包 + langgraph 依赖清理迟迟未落地**。按 P0 优先推进即可让项目回归"小而精"稳态。
