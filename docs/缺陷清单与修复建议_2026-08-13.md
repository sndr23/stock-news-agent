# 缺陷清单与修复建议（第四轮复审）

- **日期**：2026-08-13
- **范围**：全链路（`scripts/real_time_push.py` + `src/` 核心模块 + 测试 + CI + 依赖）
- **基线**：390 项单元测试全部通过；本轮为代码审查 + 针对性运行时验证（非改动）
- **前置结论**：前四轮修复（漏推直通、噪声过滤、同事件合并、tech_override 排除等）均已落地且经测试保护；本轮发现的是**尚未覆盖的新缺陷**，按严重程度分级如下。

---

## P1 级（影响核心业务正确性，建议尽快修复）

### P1-1 LLM 输出类型防御缺失 → 拆字 bug（可复现，已实证）

**现象**：LLM 返回 `sectors` / `entities` 为**字符串**（而非 JSON 数组）时，多处 `set(str)` / `join(str)` 会把字符串拆成单个字符。

**实证**：
```
' '.join('半导体')        → '半 导 体'      （含空格）
_has_tech_keyword('半 导 体') → False        （子串"半导体"被空格打断）
_has_tech_keyword('半导体')   → True
_sectors_overlap('半导体', ['半导体','AI算力']) → {'半','导','体'}   （单字误判交集）
```

**受影响路径**（全部链入生产主流程）：
| 位置 | 后果 |
|---|---|
| `_llm_judge` → `"sectors": e.get("sectors") or []` | 字符串原样透传，下游全部分解 |
| `_push_event_sig` 的 `sectors`/`entities` 集合推导 | 拆字 → 事件签名失真 → 同事件合并/跨轮去重失效 |
| `_is_domestic_tech` / `_is_overseas_tech` 的 `' '.join(sectors)` | 科技词匹配失效 → **科技兜底放行静默失效（漏推科技硬事件）** |
| `_sectors_overlap` / `_topic_saturated` | 单字交集 → 同题材饱和计数失真（误并/漏并双向） |
| `format_push_alert` 的 `"、".join(sectors[:4])` | 显示 "半、导、体" |
| `_event_signature_light` 的 `set(news.get("affected_stocks") or [])` | 若 `affected_stocks` 为字符串同样拆字（当前数据源传 list，属防御缺口） |

**修复建议**：新增一个共享防御函数，三处统一调用：
```python
def _as_list(v):
    if v is None:
        return []
    if isinstance(v, str):
        return [v]          # 字符串 → 单元素列表，杜绝拆字
    if isinstance(v, (list, tuple, set)):
        return list(v)
    return []
```
并在 `_llm_judge` 组装判定时对 `sectors`/`entities` 先过 `_as_list`，`_event_signature_light` 对 `affected_stocks` 同做防御。建议同步补 2 个单测（字符串 sectors 的 tech_override 仍生效、字符串 entities 不与字符级误并）。

### P1-2 `watchlist.json` 为空 → 自选龙头名单机制静默失效

**现象**：`watchlist.json` 当前为 `{"stocks": [], "sectors": []}`。`_load_leader_watchlist()` 返回空集，`_hit_watchlist()` 恒为 False。

**影响**：
- `_is_noise_push` 的"盘面异动龙头放行"（如"中际旭创表现活跃"应放行）只剩 LLM `is_leader_stock` 单通道；
- `_tech_override_enabled` 的龙头判定同理退化为单通道；
- README/注释声称"LLM 判定 或 命中自选龙头名单"双通道，实际第二通道未启用。

**修复建议**（二选一）：
1. 填入实际关注名单（名称即可，如 `{"stocks": [{"name": "中际旭创"}]}`）；或
2. 维持空名单但**在启动日志中显式提示**"watchlist 为空，龙头放行退化为 LLM 单通道"，避免静默降级。

## P2 级（健壮性 / 一致性 / 展示）

### P2-1 环境变量 `int()` 无防御 → 非法值直接崩溃

- `TOPIC_PUSH_LIMIT = int(os.getenv("RT_TOPIC_LIMIT", "5"))` 在**模块 import 时求值**——值非法（如 `RT_TOPIC_LIMIT=abc`）则整个脚本无法导入，云端 CI 也会直接失败；
- `RT_POLL_SECONDS`（`main` 中）与 `RT_MAX_CANDIDATES`（`run_once` 中）同理，非法值分别导致 `--loop` 启动崩溃 / 单轮 traceback。

**修复建议**：统一封装 `_env_int(name, default)`（try/except + 日志警告 + 回退默认值），模块级与运行时的取值全部改用它。

### P2-2 LLM 返回 `"score": null` 时推送正文显示 "None"

`_llm_judge` 中 `"score": e.get("score", 0)` —— 若 LLM 返回 `"score": null`，`e.get` 命中 key 返回 `None`；`_passes_threshold` 内部用 `_to_float` 无碍，但 `format_push_alert` 直接 `f"**影响分**: {score}"` 输出 "影响分: None"。

**修复建议**：`format_push_alert` 中 `score = _to_float(judge.get("score"))` 后再格式化。

### P2-3 本地 `requirements.txt` 缺 `chinese_calendar`

`_is_trading_day()` 优先 import `chinese_calendar`，仅在 `requirements-cloud.txt` 中有。本地 `RT_ALWAYS_ON=0` 时节假日（如国庆）判断退化为 `weekday()<5`，与云端行为不一致。

**修复建议**：把 `chinese_calendar>=1.9.0,<2.0.0` 同步到 `requirements.txt`。

### P2-4 LLM 总超时熔断粒度为"批次"，300s 预算实际可能超时

`_llm_judge` 的 deadline 在**批次循环入口**检查，但单批 `_call_llm_api(timeout=90, max_retries=1)` 最坏 90+2+90=182s。日志实证（2026-08-07）：单轮 LLM 判定实际耗时约 380s，超过 300s 熔断预算——虽未突破 Actions 10min 上限，但预算形同虚设，且每批挂起 8 条导致大量候选涌入 pending 重试。

**修复建议**：单批超时从 90s 降至 60s；熔断检查同时放入批次内（`_call_llm_api` 已支持 deadline，可在批次完成后再判一次剩余预算决定是否提前终止后续批次）。

### P2-5 企业微信错误响应（HTTP 200 + errcode≠0）仍白重试 2 次

`_post_with_retry` 的"4xx 不重试"判断只看 HTTP status。企业微信 token 错误、机器人被移除等场景返回 HTTP 200 + `errcode` 非 0，会重试 2 次（浪费约 6s 且延迟失败反馈）。

**修复建议**：对已知不可重试的 `errcode`（如 93000/93008/45009 等）在 `push_via_wecom` 的成功判定处短路返回。

### P2-6 `--loop` 模式日志配置不一致

`config.py` 已通过 `logging.basicConfig` 配置 StreamHandler + FileHandler（`logs/agent.log`），但 `main()` 内再次调用 `logging.basicConfig`（无 handlers 参数）为 no-op——loop 日志实际仍写文件，但 `main()` 里的格式声明不生效，两份配置并存易误导。

**修复建议**：删除 `main()` 内的重复 `basicConfig`（或改为仅当 root 无 handler 时配置）。

## P3 级（设计取舍 / 建议）

### P3-1 `_is_same_event` 分支 7（sectors 交集 + 行情措辞）存在误并漏推风险

两条**不同个股**的行情新闻若共享板块（如"英伟达上涨3%"与"AMD上涨5%"同属半导体/美股），sectors 精确交集 + 同市场域 + 行情措辞 → 被合并为同事件，只推一条。注释已声明这是用户认可的取舍（少推优于重复推），但可加轻量守卫降低误并：合并前要求"实体模糊重叠 或 标题 LCS≥3"。

### P3-2 `run_once` 主流程无端到端测试

`tests/test_e2e_regression.py` 实际覆盖的是 **DEPRECATED 批处理管线**（`src.agent.nodes`），实时推送主流程（抓取→去重→指纹→预筛→LLM→合并→推送→状态）没有 mock 级 e2e 测试。`_tech_override_enabled`、`_topic_saturated`、`_is_noise_push` 的"字符串类型路径"（P1-1）也无测试。

**修复建议**：补一个 mock 数据源的 `run_once` 集成测试（patch 抓取与 LLM 返回固定值，断言推送条数与状态落盘），成本低、防回归价值高。

### P3-3 全局副作用：`os.chdir(PROJECT_ROOT)` + `sys.path.insert`

`real_time_push.py` 在模块 import 时执行 `os.chdir(PROJECT_ROOT)`，任何 import 该模块的进程 cwd 被改写（测试用 try/finally 恢复）。建议仅保留 `sys.path` 注入，cwd 交由调用方/入口控制。

### P3-4 Gist Token 最小权限建议

`GIST_TOKEN` 建议使用**仅含 gist scope** 的 Fine-grained PAT，避免主仓库写权限的 token 长期存在于本地 `.ENV` 与云端 Secrets。另：`.ENV` 若被意外提交会有密钥泄露风险，建议 `.gitignore` 中再次确认（当前已被忽略则无需处理）。
