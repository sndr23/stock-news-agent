05 · 资讯管线核心设计（10 步）

  1. 抓取 — 8 新闻源 + 2 信号源并行（单类失败不清空另一类，08-07 修复）
  2. 三层近似去重 — URL 规范化 → 标题精确 → 32-bit SimHash（信号类模板标题豁免）
  3. 事件级指纹增量 — 个股+事件组+核心金额 / 信号词（宽泛词排除）/ 标题主语前 6 字，48h 窗口，SEEN_MAX=3000
  4. 规则预筛 — 评分 ≥0.55 或高信号词；宏观数据发布 / 大额经营事件 / 科技龙头主体词三层兜底直通；溢出按「高信号>宏观>预筛分」分层排序挂起（≤3 轮）
  5. LLM 严格判定 — 全部候选必须经 LLM；idx 精确对齐（实证标题仅 26/60 命中）；未回显挂起不落指纹；300s 总熔断（批次入口+完成双重检查）；JSON 容错五连
  6. 同事件合并 — 推送级事件签名：实体模糊重叠 + 事件短语锚 + LCS 连续/子序列 + Jaccard + 方向守卫 + 央行实体/宏观数据/市场时段域（10+ 分支）
  7. 强档门槛 — 仅 bullish/bearish 推送（08-04 用户口径），覆盖全部路径
  8. 噪声硬过滤 — 栏目汇总/指数播报/盘面异动（栏目内嵌重大事件放行），即使 LLM 判强档
  9. 跨轮拦截 + 饱和限流 — 48h 同事件已推拦截；同题材 24h ≤5（market 级豁免）
  10. 推送 + 状态 — 推送失败不落指纹下轮重试；Gist 读-改-写合并 + fail-stop（8-13 P0 事故教训）

8-19 增强：推送卡附「市场环境」单行（贴水/日元/上证/主力资金/隔夜外盘/高波/情绪极端值）；LLM 注入量化环境上下文输出共振/背离 env_note；近 48h 同主体已推事件注入 related_recent（叙事链），反向事件附矛盾提示。

06 · 因子管线核心设计

6.1 六维方向合成（IC 加权 + 门控）

维度打分逻辑数据来源
对冲IC/IM 贴水收敛=+1、走扩=-1（相对基线，非常态阈值）新浪股指期货
风险risk_off=-1（贴水走扩/日元急升/放量破位/跌停潮/GC007≥3.5% 任一触发）异动检测聚合
量价放量突破=+1、放量破位=-1新浪日K 260 窗口
汇率日元急升（美元/日元单日≥1.5%）=套息平仓利空新浪外汇
波动率任一核心指数高波（20 日分位）=-1（机构降杠杆）K 线计算
宽度≥80% 个股下跌=-1、≤20%=+1东财 datacenter

综合分 = Σ(w×s)/Σ(w)，≥0.5 偏多 / ≤-0.5 偏空 / 否则中性；IC 加权（≥20 交易日样本，权重地板 0.1）；非线性门控（高波 → 利空维 ×1.5；极端普跌+日元急升 → 汇率/宽度 ×1.5）；影子因子（GC007 / PCR 只记录不参与合成，IC 达标后升级）。方向变化且 |score|≥0.67 才单独推送，弱翻转进简报。

6.2 与资讯管线的联动

factor_collector 写入 risk_state + 快照至 Gist（一次读取三用：LLM 环境上下文 / 市场环境行 / 简报数据源）。risk_off 时资讯管线对「无硬事件佐证的科技利好」（无金额/无百分比/无完成态动词，且动词前无「有望/拟」等展望修饰）降级不推——与量化资金风险期降杠杆一致；利空/风险资讯不受影响。

08 · 本次审读新增发现（本版核心增量）

🔴 P0-1｜8-19 P0-P7 全部成果尚未提交 git

git status 实测：scripts/real_time_push.py、scripts/factor_collector.py、5 个测试文件、watchlist.json 均已修改未提交；market-brief.yml、signal-backtest.yml、signal_backtest.py、7 个新测试文件、docs/quant-tracker-analysis/ 全部未跟踪。最新提交仍是 8-13 的 d88a6fe。今日批量上线的全部功能仅存在于工作区，本地磁盘损坏即整体丢失，且云端 Actions 无法取到未提交代码。建议立即 commit（含 4 个新 workflow 与测试）。

🔴 P0-2｜信号回测当前空转：64 条已推事件全部「未标注方向」

logs/signal_quality_report.md 实测：近 14 天 64 条已推事件，可评估 0 条，跳过原因「未标注方向 64」。根因：pushed_events 的 dir 字段为 8-19 新增（P0-3），Gist 中历史条目均无该字段，而 signal_backtest.py 对无 dir 的条目一律跳过。回测链路「推送方向 vs 后 1/3/5 日行情一致率」目前无法产出任何结论。建议：①接受冷启动，约需 2-4 周积累有 dir 标注的样本；②或对历史条目按 LLM 判定方向回填（需谨慎：历史判定未存方向，回填需重跑 LLM，成本高）；③至少在报告中明确「样本积累中」状态，避免误读为「回测通过」。

🟡 P1-1｜factor_state.json 快照与顶层 risk_state 不一致

实测快照（ts=17:21）内 risk_state=risk_off（上证 -2.40%、创业板 -6.26% 大跌日），但顶层 risk_state=neutral。属「快照记录当时、顶层记录最新」的设计，但若快照消费方（简报/环境行）与联动判定（顶层）读到不同值，可能在 risk_off 当日展示「⚠️风险收缩期」却对科技利好不降级。建议核验快照写入与顶层更新的时序一致性。

🟡 P1-2｜双科技词表仍未合并（延续风险）

real_time_push.py 内嵌 _TECH_SECTOR_WORDS（降级判定宽词，含液冷/散热/数据中心等）与 keyword_tables.py 的 OVERSEAS_TECH_KEYWORDS（外围科技增强，已收敛硬科技词）各维护一份，注释亦承认「缺液冷/散热/数据中心」。降级判定与外围增强是两个语义，建议分名并入共享词表，杜绝一词两义漂移。

🟢 P2-1｜LLM 判定 score 未防御转 float（下游已兜底）

_llm_judge 写入 results[i]["score"] = e.get("score", 0) 未做类型转换；依赖 _passes_threshold / _to_float 在消费端兜底。当前不构成故障，但与 _as_bool/_as_list 的「字段入口即防御」惯例不一致，建议在判定结果构造时统一转换。

🟢 P2-2｜数据源实测全绿，双端同跑风险仍在

agent.log 实测 8 源全部成功；但代码注释明确「本地 --loop 与云端共享 Gist 双端同跑浪费 LLM 额度且偶发重复」，读-改-写合并只能缩小窗口不能根除。建议生产环境明确单一运行端（仅云端），本地仅用于开发调试。

10 · 总体结论

产品层面（成熟）：已实现「财联社式」重大消息推送，8-13 日本加息漏推事件驱动完成了从「单维个股利好」到「多维量化因子均衡」的架构转向；8-19 P0-P7 批量上线后，融合展示（市场环境行/盘前盘后简报/共振背离标注）与验证闭环（信号回测/因子 IC）均已就位，方向正确。

工程层面（扎实）：实证驱动 + 防御式编程 + 672 项测试门禁 + 多轮人工审核闭环是最大资产；8-13 P0 状态事故后的 fail-stop 加固与体积上限设计到位。主要负债是单文件巨型化与规则分支复杂度。

数据层面（可信）：8 新闻源 + 2 信号源 + 12 类因子数据互为备份、实测全绿；免费接口为主、成本可控。

优先级建议：① 立即提交 8-19 全部改动（防止成果丢失）；② 明确信号回测样本积累期口径；③ 短期收敛双科技词表、明确单一运行端；④ 中期去重模块化 + 清理废弃 LangGraph；⑤ 长期以回测数据驱动阈值与 Prompt 迭代。
