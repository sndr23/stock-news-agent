# 任务：创业板量化择时系统深度优化分析（只做分析，不改任何代码）

## 背景
这是一个 A 股创业板 ETF 场外基金择时系统（版本 v5.1）：每个交易日 14:45 输出目标仓位档位（0/60/90/100%），用户在 15:00 前手动申赎，按当日收盘净值成交，赚次日及以后的收益。用户是价值投资者，懂量化（IC/walk-forward/夏普/卡玛）和缠论。

铁律：任何策略改动必须附带回测且不低于基线；OOS 期间不调参。

## 必读文件（工作目录 = 项目根）
1. `src/strategy/chinext_timing.py` —— 择时核心策略（约 550 行）
2. `scripts/run_chinext_timing.py` —— 每日运行入口（约 1480 行）
3. `src/strategy/chinext_factors.py` —— 因子库
4. `src/strategy/chan_light.py` —— 缠论轻量模块（若被择时引用）
5. `docs/创业板择时系统说明_20260822.md` —— 系统设计说明
6. `docs/策略缺陷实验报告_20260828.md` 与 `docs/缺陷诊断与推进方案_20260828.md` —— 已知缺陷与实验结论（避免重复提已否决的方案）
7. `docs/needs-decision.md`、`docs/status.md` —— 当前待决策项与状态

## 分析要求
逐文件读完核心代码后，输出一份优化分析报告，结构如下：

1. **系统现状速览**：信号链路图（数据→因子→打分→档位→推送），当前参数一览。
2. **发现的问题与优化机会**，按 P0（明显缺陷/亏钱风险）、P1（稳健性提升）、P2（锦上添花）分级。每条必须包含：
   - 证据：具体文件+行号+代码片段引用，不许凭空推断；
   - 问题机理：为什么这样设计会出问题（过拟合风险/前视偏差/数据依赖/边界条件/状态机等）;
   - 建议改法：具体可执行的方案；
   - 验证方式：如何用回测确认改动不低于基线（指出可复用的回测脚本，如 scripts/signal_backtest.py）。
3. **重点检查方向**（但不限于）：
   - 前视偏差：14:45 时点能看到的数据 vs 回测所用数据是否一致（收盘数据混入盘中决策？）；
   - 档位切换的换手成本与信号翻转抖动（0↔60↔90↔100 边界是否有滞回/确认机制）；
   - 参数敏感性：哪些阈值是硬编码的、对样本期是否过拟合；
   - 数据源断流降级路径：腾讯/东财/新浪接口失败时策略输出什么？是否有静默失效风险；
   - walk-forward / OOS 验证是否完整，还是全样本调参；
   - 缺失的信号维度（如成交量能突变、北向/融资、跨市场相关性）是否有低成本引入方式。
4. **不建议做的事**：明确列出看似合理但你认为不值得改的地方及理由。
5. **优先级路线图**：如果只做 3 件事，做哪 3 件，预期收益/风险比。
