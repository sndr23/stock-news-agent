## 一、结论先行

1. **本质是两套系统，不是传统意义的"量化程序"**：一套是「事件驱动资讯推送」（LLM 判定 + 去重 + 微信），一套是「创业板单资产择时」（9 个注册因子、8 个有效因子打分 + 仓位状态机）。真正的"量化"内核集中在后者 + `factor_collector` 的因子采集 + `signal_backtest` 的 IC 验证；资讯线是**软信号/信息流系统**。
2. **最强项是去重与容错工程，而非 alpha**：事件级指纹 + 推送级同事件签名（13 个合并分支、实体别名归一、LCS 双实现、方向守卫）是全项目最扎实的部分，且每个分支都有"实证修复"背书；Gist 状态的 fail-stop 容错同样到位。
3. **最需审慎的是回测数字的解读**：当前严格信息集回测为策略累计 **+105.3%**、年化 **+6.2%**、夏普 **0.46**、最大回撤 **-42.1%**；买入持有 **+170.1%**、最大回撤 **-69.7%**。首轮 walk-forward OOS 为策略 **+64.6%**、年化 **+5.7%**、夏普 **0.41**、最大回撤 **-27.8%**，仍低于买入持有 **+111.2%**；计入单次换仓成本 0.3% 后，OOS 降至 **+19.0%**、年化 **+2.0%**、夏普 **0.20**、最大回撤 **-38.3%**。当前证据支持“改善回撤”，不支持“跑赢买入持有”或存在稳定 alpha。旧文档中的 +309.5%/+291.9%/+188.8% 属于历史宽松信息集或旧配置口径，仅作对照。
4. **信任基石目前是空缺的**：`signal_backtest` 的"推送方向一致率"是设计的可信度底座，但 `dir` 字段 2026-08-19 才上线，当前处于**冷启动**，尚无统计结论——资讯系统"信号是否有效"暂时无法量化，这与项目"先验证、再优化"的纪律之间存在张力。
5. **当前工程风险集中在状态并发、外部调度和免费源可用性**：Gist 读-改-写仍非原子（高）；外部定时服务与 GitHub Actions 的最近实际运行记录尚未核验（中）；免费 HTTP 源无 SLA，东财、Yahoo/Stooq 已出现反爬或限流实证（中低）。此前的 `config.py` import 防护、挂起条目处理、去重复杂度治理和基金轮动入口问题已完成修复，不再列为当前故障。

## 三、资讯推送管线评估（软信号系统）

**强项（工程成熟度高）**

- **事件级指纹 + 推送级同事件签名双去重**：`_news_fingerprint` 解决"同一条"，`_is_same_event`（160 行 / 13 分支）解决"同一事件的不同报道"。实体别名归一（大摩=摩根士丹利）、板块子串包含（"AI算力"⊂"AI/算力"）、LCS 连续子串 + 子序列双实现、涨跌方向守卫、鹰鸽政策方向守卫——每个分支都标注了对应实证事故（恩智浦收购三推、索尼×台积电三推、日本央行加息三推、纳指三推）。
- **状态 fail-stop 容错**：Gist 读 3 次重试 + `?ts=` 绕 CDN 缓存；读不到 / JSON 损坏 / 缺 `seen` 键一律报错拒绝空状态运行（曾因此冲掉 4759 条去重基准）。seen 上限 3000 条、pending 上限 200、pushed_events 上限 300，体积控制 <1MB。
- **漏推保护链完整**：LLM 未回显/批次失败 → 挂起下轮重试（不落指纹）；候选溢出 → pending 挂起（高信号永不放弃）；300s 总超时熔断；心跳告警区分"确实没大事"与"系统静默故障"。

**弱项（诚实标注）**

- **"信号"本质是 LLM 主观判断**：方向由 6 档 LLM 判定 + `_normalize_direction` 的大量别名映射/规则兜底输出，非硬数据驱动。`_normalize_direction` 的别名表（看涨/利多/强利好/偏多…）长度本身就说明 LLM 输出不稳定。这是**软信号系统**，不是硬因子系统。
- **去重复杂度过高**：`_is_same_event` 13 分支是"打地鼠式"维护的产物——每遇新漏推/误推就加一个守卫分支。这是硬问题的证据，但也说明底层抽象（手写字符串规则）已到极限，嵌入向量/相似度检索可能是更可持续的替代。
- **数据源全部为免费 HTTP 抓取**：akshare/新浪/腾讯/东财/财联社/华尔街见闻/金十。东财 push2his 已被反爬（RemoteDisconnected 实证），UA 轮换 + 多主机 fallback + 三冗余是**缓解不是根治**，无官方数据 vendor 兜底。

## 四、创业板择时系统评估（真正的"量化"内核）

**架构清晰（值得肯定）**

- **可回测 / 不可回测分层**：核心层 9 个注册因子只用 399006 日线（close+amount），其中 `value_erp` 当前关闭，实际 8 个有效因子参与打分；修正层（贴水/资金/情绪/资讯 + 缠论 + 旭创）总分**有界 ±0.30**，资金/情绪/资讯另有 ±0.05/±0.04/±0.06 分项上限，明确"实时数据只能倾斜不能定档"。
- **无前视纪律**：t 日信号只用 ≤t-1 收盘 + t 日盘中涨跌幅，吃 d+1 收益（对齐场外基金 T+1）。
- **验门纪律真实执行**：`|IC|≥0.05 且样本≥10` 才进核心层，已据此关闭业绩预告（退化为常数）、两融、外盘打分（全样本 IC<0.05）等不达标因子。**估值维上（样本外负贡献后）已降到两套处理**：① 打分维彻底关闭（`erp_pctile=None`，不再参与 9 个注册因子的核心合成）；② ERP 估值极端滤波（便宜度分位<0.10 封顶 6 成）仅作为独立硬风控接入，即估值不参与核心打分，只在极端贵时强制降仓（详见附注 A）。

**回测数字需审慎解读（关键）**

| 口径 | 数值 | 审慎解读 |
|---|---|---|
| 严格全历史策略 / 持有 | **+105.3%** / +170.1% | 策略跑输买入持有；平均仓位 44%，主要价值仍是控制回撤 |
| 年化 / 夏普 / 最大回撤 | **+6.2% / 0.46 / -42.1%** vs 持有 -69.7% | 回撤改善是当前最明确的证据，绝对收益仍低于持有 |
| 首轮 OOS（无成本） | **+64.6% / +5.7% / 0.41 / -27.8%** | 9 折滚动测试仍跑输持有 +111.2%，参数跨折漂移 |
| 首轮 OOS（单次换仓成本0.3%） | **+19.0% / +2.0% / 0.20 / -38.3%** | 成本敏感，不能把无成本 OOS 当作可交易收益承诺 |
| 因子权重来源 | 趋势0.35/量价0.20/波动0.20/估值0.10/落袋0.15 | 当前生产权重仍来自历史配置；OOS 参数跨折漂移，存在过拟合风险 |
| ERP 极端滤波 | 便宜度分位<0.10 封顶 6 成 | 当前仅作独立保守风控，不进入核心打分；历史宽松口径的收益变化不能作为当前验收依据（详见附注 A） |
| 旭创侧 | 夏普0.99/回撤-58.8%/+2620% | 报告已自标"幸存者偏差，不可当真"，诚实 |

**结构性风险**

- **单资产、无截面验证**：全部信号押在 399006 一个指数上，无横截面分组检验（FACTOR_REGISTRY 注释明确"不搬 Alphalens 截面分组"）。作为个人工具可接受，但模型集中度风险高——一旦创业板与历史 regime 背离，整个系统失效。
- **择时与持仓的错配风险**：用户实际持有的是"重仓中际旭创的场外基金"，系统用创业板指数做主信号 + 旭创做情绪确认。但旭创 beta≈2.0、回撤 -58.8%，意味着信号对（指数）不等于净值对（基金），这是系统定位层面的固有张力，需持续用影子期数据验证。

## 五、信号回测与可信度（当前最大缺口）

`signal_backtest.py` 是设计的"可信度基石"：用 `pushed_events` 历史统计"推送方向 vs 后 1/3/5/10 日行情一致率"，并做分层 IC（P11，Alphalens 单调性思路的时序落地）与因子 IC（P4-6，Spearman，自实现无 scipy）。

**但当前处于冷启动**：`dir` 字段 2026-08-19 才写入 `pushed_events`，历史事件无方向标注，报告已明确标注"样本冷启动中"。这意味着：

- **资讯推送系统的"信号有效性"目前无法量化**——与项目"先验证、再优化"的纪律存在张力；
- 按强档推送节奏，约 2–4 周后分组一致率才有统计意义。在此之前，所有阈值/LLM prompt 调优都缺乏量化反馈闭环。

## 七、改进建议（按优先级）

1. **继续建立样本外验证闭环**（对齐"先验证"纪律）：严格信息集和首轮 walk-forward 验证器已经收口，但 OOS 仍跑输买入持有；继续积累 2026-08-22 之后留出样本与 `signal_backtest` 资讯样本，不把 OOS 最优参数写回生产，也不针对全历史反复调权重。
2. **根治 Gist 并发**：Gist API 支持 ETag/`If-Match`，或改用单写端 + 数据库（如 SQLite on Cloudflare D1 / Supabase），消除双端 last-write-wins。
3. **降低去重复杂度**：评估以嵌入向量相似度（本地 sentence embedding 或 LLM embedding）替代/兜底 13 分支字符串规则，减少规则维护风险。
4. **收口依赖一致性**：生产入口已经与 `langchain_core` 解耦；后续仅需在不影响历史测试的前提下收敛可选兼容层和废弃模块边界。
5. **数据源加固**：关键源已采用免费多源回退、本地缓存和新鲜度校验；当前继续观察外盘免费双源冗余，增强维度缺失时明确降级。免费源连续失败 3 轮已可触发健康告警。
6. **明确定位标注**：在报告/推送中标注"资讯为 LLM 主观判定、择时为单资产历史/OOS 观察结果"，避免将软信号与硬量化混为一谈。

## 附注 A：ERP 估值极端滤波 —— 语义反转 bug 纠正记录（2026-08-22 二次修订）

> **重要勘误**：本附注首版（commit `c0df5bd`）记录的"+291.9%→+309.5%"**建立在估值滤波语义反转的 bug 上**，已于本次审查发现并纠正。以下为纠正后的正确记录。

**背景**：创业板择时核心层此前因"估值维样本外负贡献"将 `value_erp` 打分关闭。外部审查建议"估值应作大周期滤波而非日频主信号"，据此重新引入估值作为独立硬风控（不参与打分）。

**bug 与纠正**：`index_pe.pe_to_cheap_pctile` 返回的是**便宜度**（cheap 高=便宜→看多，低=贵→看空），但首版实现误用 `>0.90` 作触发——即**便宜度>0.9（估值极便宜）时封顶**，与注释声称的"极贵封顶"完全相反。纠正为 `便宜度<0.10`（=PE 处于 500 日顶部 10%，**估值极贵**）时封顶 6 成。生产 `score_all` 与回测 `backtest_metrics` 两处均已在 commit 同步纠正。

**纠正后验证（full-range 2014-07 ~ 2026-08，confirm 状态机 + 满仓≥0.40）**

| 口径 | 累计 | 夏普 | 回撤 | 卡玛 |
|---|---|---|---|---|
| bug 版（便宜时封顶，已弃） | +309.5% | 0.71 | -38.5% | 0.32 |
| **纠正后（极贵时封顶，历史宽松信息集/旧配置）** | **+188.8%** | 0.60 | -42.0% | **0.22** |
| 无估值滤波（基线） | +291.9% | 0.68 | -42.8% | 0.28 |
| 买入持有 | +171.3% | — | -69.7% | 0.12 |

**教训（数据实证）**：bug 版本"便宜时封顶"之所以虚增收益，是因为彻底利用了 2015 泡沫后 PE 长时间处于 500 日底部的窗口——那段阴跌期被持续降仓"躲过"，制造了本不该存在的超额。纠正方向后，估值滤波反而**下拉收益**（+291.9%→+188.8%）且卡玛下降（0.28→0.22），即**对创业板而言，"估值极贵时降仓"的估值极端滤波实际是净负贡献**。这也与早年"估值维样本外负贡献关闭"的结论一致。

**最终决策（用户拍板保留极贵封顶）**：尽管纠正语义后 ERP 滤波为净负贡献（+188.8% vs 基线 +291.9%，卡玛 0.22 vs 0.28），**用户选择保留"估值极贵封顶"**作为当时的生产配置。该结果属于历史宽松信息集/旧配置对照，定位为**保守度更高的变体**：牺牲 ~103pp 收益换取对"历史 500 日顶部估值区间的强制降仓"，作为市场泡沫期的事前约束。基线 +291.9% 作为无估值滤波对照口径保留在报告中；当前生产表现和验收基线以严格信息集结果为准（策略 +105.3%，买入持有 +170.1%）。
