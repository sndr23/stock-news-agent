## 一、结论先行

1. **本质是两套系统，不是传统意义的"量化程序"**：一套是「事件驱动资讯推送」（LLM 判定 + 去重 + 微信），一套是「创业板单资产择时」（10 因子打分 + 仓位状态机）。真正的"量化"内核集中在后者 + `factor_collector` 的因子采集 + `signal_backtest` 的 IC 验证；资讯线是**软信号/信息流系统**。
2. **最强项是去重与容错工程，而非 alpha**：事件级指纹 + 推送级同事件签名（12 个合并分支、实体别名归一、LCS 双实现、方向守卫）是全项目最扎实的部分，且每个分支都有"实证修复"背书；Gist 状态的 fail-stop 容错同样到位。
3. **最需审慎的是回测数字的解读**：创业板择时"策略 +309.5% / 持有 +171.3%"的超额，主要来自**熊市低仓位（平均仓位 52%）而非方向预测能力**——降档后 10 日仅 51% 段为下跌，出场侧几乎无预测优势；且因子权重、ERP 估值滤波均经"收益矩阵寻优"，属同一样本 in-sample 调参，存在过拟合风险（详见附注 A）。
4. **信任基石目前是空缺的**：`signal_backtest` 的"推送方向一致率"是设计的可信度底座，但 `dir` 字段 2026-08-19 才上线，当前处于**冷启动**，尚无统计结论——资讯系统"信号是否有效"暂时无法量化，这与项目"先验证、再优化"的纪律之间存在张力。
5. **工程债集中在三处**：Gist 读-改-写非原子（高）、`config.py` import 副作用清除代理（中）、`data_fetchers.py` 仍引用 `langchain_core.tools.tool` 但依赖未 pin（与 README"零 langchain 依赖"表述不一致，中低）。

## 三、资讯推送管线评估（软信号系统）

**强项（工程成熟度高）**

- **事件级指纹 + 推送级同事件签名双去重**：`_news_fingerprint` 解决"同一条"，`_is_same_event`（160 行 / 12 分支）解决"同一事件的不同报道"。实体别名归一（大摩=摩根士丹利）、板块子串包含（"AI算力"⊂"AI/算力"）、LCS 连续子串 + 子序列双实现、涨跌方向守卫、鹰鸽政策方向守卫——每个分支都标注了对应实证事故（恩智浦收购三推、索尼×台积电三推、日本央行加息三推、纳指三推）。
- **状态 fail-stop 容错**：Gist 读 3 次重试 + `?ts=` 绕 CDN 缓存；读不到 / JSON 损坏 / 缺 `seen` 键一律报错拒绝空状态运行（曾因此冲掉 4759 条去重基准）。seen 上限 3000 条、pending 上限 200、pushed_events 上限 300，体积控制 <1MB。
- **漏推保护链完整**：LLM 未回显/批次失败 → 挂起下轮重试（不落指纹）；候选溢出 → pending 挂起（高信号永不放弃）；300s 总超时熔断；心跳告警区分"确实没大事"与"系统静默故障"。

**弱项（诚实标注）**

- **"信号"本质是 LLM 主观判断**：方向由 6 档 LLM 判定 + `_normalize_direction` 的大量别名映射/规则兜底输出，非硬数据驱动。`_normalize_direction` 的别名表（看涨/利多/强利好/偏多…）长度本身就说明 LLM 输出不稳定。这是**软信号系统**，不是硬因子系统。
- **去重复杂度过高**：`_is_same_event` 12 分支是"打地鼠式"维护的产物——每遇新漏推/误推就加一个守卫分支。这是硬问题的证据，但也说明底层抽象（手写字符串规则）已到极限，嵌入向量/相似度检索可能是更可持续的替代。
- **数据源全部为免费 HTTP 抓取**：akshare/新浪/腾讯/东财/财联社/华尔街见闻/金十。东财 push2his 已被反爬（RemoteDisconnected 实证），UA 轮换 + 多主机 fallback + 三冗余是**缓解不是根治**，无官方数据 vendor 兜底。

## 四、创业板择时系统评估（真正的"量化"内核）

**架构清晰（值得肯定）**

- **可回测 / 不可回测分层**：核心层 10 因子只用 399006 日线（close+amount），12 年可回测；修正层（贴水/资金/情绪/资讯 + 缠论 + 旭创）**有界 ±0.30**，明确"实时数据只能倾斜不能定档"——核心 0 分时四项修正拉满也只有 +0.30 < 满仓线 0.40，从结构上防止不可回测数据越权。
- **无前视纪律**：t 日信号只用 ≤t-1 收盘 + t 日盘中涨跌幅，吃 d+1 收益（对齐场外基金 T+1）。
- **验门纪律真实执行**：`|IC|≥0.05 且样本≥10` 才进核心层，已据此关闭业绩预告（退化为常数）、两融、外盘打分（全样本 IC<0.05）等不达标因子。**估值维上（样本外负贡献后）已降到两套处理**：① 打分维彻底关闭（`erp_pctile=None`，不再参与 10 因子合成）；② 但 2026-08-22 新增 ERP 估值**极端滤波**（便宜度分位>0.90 封顶 6 成）作为独立硬风控接入——即估值不再"打分"，只在极端贵时强制降仓（详见附注 A）。这是全项目最"量化"的地方。

**回测数字需审慎解读（关键）**

| 口径 | 数值 | 审慎解读 |
|---|---|---|
| 策略累计 / 持有 | **+309.5%** / +171.3% | 超额约 138pp，但**平均仓位仅 52%**——超额主要来自熊市降仓，非方向预测 |
| 夏普 / 卡玛 | 0.71 / 0.32 | 相对持有（卡玛 0.12）确有改善，但绝对水平一般 |
| 最大回撤 | **-38.5%** vs 持有 -69.7% | 这是最实在的改善项 |
| 降档质量 | 174 次减仓后 10 日 51% 为下跌 | **出场侧几乎无预测优势**（≈掷硬币），进一步佐证"超额来自仓位而非择时" |
| 因子权重来源 | 趋势0.45/量价0.20/波动0.20/估值0.10/落袋0.15 | 经"收益矩阵寻优"→ 12 年同一样本 in-sample 调参，**存在过拟合风险**，需严格样本外验证 |
| ERP 极端滤波 | 便宜度分位>0.90 封顶 6 成 | 2026-08-22 新增，收益 291.9→309.5%、回撤-42.8→-38.5%、样本外卡玛 0.44→0.41（详见附注 A） |
| 旭创侧 | 夏普0.99/回撤-58.8%/+2620% | 报告已自标"幸存者偏差，不可当真"，诚实 |

**结构性风险**

- **单资产、无截面验证**：全部信号押在 399006 一个指数上，无横截面分组检验（FACTOR_REGISTRY 注释明确"不搬 Alphalens 截面分组"）。作为个人工具可接受，但模型集中度风险高——一旦创业板与历史 regime 背离，整个系统失效。
- **择时与持仓的错配风险**：用户实际持有的是"重仓中际旭创的场外基金"，系统用创业板指数做主信号 + 旭创做情绪确认。但旭创 beta≈2.0、回撤 -58.8%，意味着信号对（指数）不等于净值对（基金），这是系统定位层面的固有张力，需持续用影子期数据验证。

## 五、信号回测与可信度（当前最大缺口）

`signal_backtest.py` 是设计的"可信度基石"：用 `pushed_events` 历史统计"推送方向 vs 后 1/3/5 日行情一致率"，并做分层 IC（P11，Alphalens 单调性思路的时序落地）与因子 IC（P4-6，Spearman，自实现无 scipy）。

**但当前处于冷启动**：`dir` 字段 2026-08-19 才写入 `pushed_events`，历史事件无方向标注，报告已明确标注"样本冷启动中"。这意味着：

- **资讯推送系统的"信号有效性"目前无法量化**——与项目"先验证、再优化"的纪律存在张力；
- 按强档推送节奏，约 2–4 周后分组一致率才有统计意义。在此之前，所有阈值/LLM prompt 调优都缺乏量化反馈闭环。

## 七、改进建议（按优先级）

1. **补样本外验证闭环**（对齐"先验证"纪律）：择时因子做 walk-forward 时间序列切分（滚动训练/测试），而非整段 in-sample 寻优；把 `signal_backtest` 的冷启动期作为观察期，2–4 周后据一致率反馈收紧/放宽阈值。
2. **根治 Gist 并发**：Gist API 支持 ETag/`If-Match`，或改用单写端 + 数据库（如 SQLite on Cloudflare D1 / Supabase），消除双端 last-write-wins。
3. **降低去重复杂度**：评估以嵌入向量相似度（本地 sentence embedding 或 LLM embedding）替代/兜底 12 分支字符串规则，减少打地鼠式维护。
4. **收口依赖一致性**：`data_fetchers.py` 的 `@tool` 装饰器改为纯函数（实际调用都用 `.func`），移除 `langchain_core` 隐式依赖，坐实 README"零 langchain"表述。
5. **数据源加固**：为关键源（指数日K/期货基差/汇率）引入付费或半官方数据源做冗余，免费抓取作为降级路径。
6. **明确定位标注**：在报告/推送中标注"资讯为 LLM 主观判定、择时为单资产 in-sample 结果"，避免将软信号与硬量化混为一谈。

## 附注 A：ERP 估值极端滤波 —— 语义反转 bug 纠正记录（2026-08-22 二次修订）

> **重要勘误**：本附注首版（commit `c0df5bd`）记录的"+291.9%→+309.5%"**建立在估值滤波语义反转的 bug 上**，已于本次审查发现并纠正。以下为纠正后的正确记录。

**背景**：创业板择时核心层此前因"估值维样本外负贡献"将 `value_erp` 打分关闭。外部审查建议"估值应作大周期滤波而非日频主信号"，据此重新引入估值作为独立硬风控（不参与打分）。

**bug 与纠正**：`index_pe.pe_to_cheap_pctile` 返回的是**便宜度**（cheap 高=便宜→看多，低=贵→看空），但首版实现误用 `>0.90` 作触发——即**便宜度>0.9（估值极便宜）时封顶**，与注释声称的"极贵封顶"完全相反。纠正为 `便宜度<0.10`（=PE 处于 500 日顶部 10%，**估值极贵**）时封顶 6 成。生产 `score_all` 与回测 `backtest_metrics` 两处均已在 commit 同步纠正。

**纠正后验证（full-range 2014-07 ~ 2026-08，confirm 状态机 + 满仓≥0.40）**

| 口径 | 累计 | 夏普 | 回撤 | 卡玛 |
|---|---|---|---|---|
| bug 版（便宜时封顶，已弃） | +309.5% | 0.71 | -38.5% | 0.32 |
| **纠正后（极贵时封顶）** | **+188.8%** | 0.60 | -42.0% | **0.22** |
| 无估值滤波（基线） | +291.9% | 0.68 | -42.8% | 0.28 |
| 买入持有 | +171.3% | — | -69.7% | 0.12 |

**教训（数据实证）**：bug 版本"便宜时封顶"之所以虚增收益，是因为彻底利用了 2015 泡沫后 PE 长时间处于 500 日底部的窗口——那段阴跌期被持续降仓"躲过"，制造了本不该存在的超额。纠正方向后，估值滤波反而**下拉收益**（+291.9%→+188.8%）且卡玛下降（0.28→0.22），即**对创业板而言，"估值极贵时降仓"的估值极端滤波实际是净负贡献**。这也与早年"估值维样本外负贡献关闭"的结论一致。

**最终决策（用户拍板保留极贵封顶）**：尽管纠正语义后 ERP 滤波为净负贡献（+188.8% vs 基线 +291.9%，卡玛 0.22 vs 0.28），**用户选择保留"估值极贵封顶"**作为当前生产配置。定位为**保守度更高的变体**：牺牲 ~103pp 收益换取对"历史 500 日顶部估值区间的强制降仓"，作为市场泡沫期的事前约束。基线 +291.9% 作为无估值滤波对照口径保留在报告中。核心层真实表现口径以生产配置 +188.8% 为准，对照基线 +291.9%。
