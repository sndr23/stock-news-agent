## 背景
本仓库是 A 股创业板 ETF 场外基金择时系统（v5.1）。今天的只读审计发现 P0 级缺陷，你负责修复。审计报告全文见 `docs/WB择时优化分析_deepseek_20260910.md`（先读它的 P0-1 部分）。

## 错在哪（证据 = 文件:行号，已人工核实属实）
硬风控 6 项（回撤封顶/波动分位/risk_off/期指贴水/盘中急跌/外盘急跌）中 5 项在数据源失败时 **fail-open（静默放行）**：

1. `scripts/run_chinext_timing.py:178-183`：盘中行情 `get_quotes` 失败 → `intraday` 静默置 `0.0`；
2. `scripts/run_chinext_timing.py:428-430`：该 `0.0` 被当作真实值 `intraday_pct` 送进硬风控 → "盘中急跌"检查在断流时形同虚设，甚至比缺失更糟（伪装成 +0.00% 安全）；
3. `scripts/run_chinext_timing.py:221-227`：外盘行情失败 → `overseas_drop` 静默置 0 → "外盘急跌"检查失效；
4. `scripts/run_chinext_timing.py:449-453`：PE 数据失败 → `erp` 为空 → 估值滤波不触发，无任何告警。

后果：数据断流 + 当天急跌的组合场景下，系统可能照样输出高仓位档位且推送里看不出任何异常。

## 改到什么标准（验收条件，逐条可检验）
1. **缺失显式化**：盘中/外盘/PE 任一数据源失败时，不再用 0.0 冒充真实值——用显式的"缺失"标记（None 或等价机制）传递；
2. **fail-safe**：硬风控遇到"本应用于判断的输入缺失"时，采取保守动作而不是放行：仓位封顶 `min(cap, 0.6)`，reasons 里写明哪个输入缺失（如 `intraday_missing` / `overseas_missing` / `erp_missing`）；
3. **推送可见**：当日推送/输出里包含降级告警（哪些风控输入缺失、已启用保守封顶），用户一眼能看到；
4. **正常路径零变化**：所有数据源正常时，输出与改动前完全一致（这是金标准，不得引入任何行为差异）；
5. **测试**：`python -m pytest tests/ -q -m "unit"` 全绿；并新增针对上述 4 处的单元测试（模拟数据源失败 → 断言保守封顶与告警出现；模拟全正常 → 断言与旧逻辑输出一致）；
6. **最小改动**：只动 `scripts/run_chinext_timing.py` 和必要的测试文件，不重构、不动策略核心 `src/strategy/chinext_timing.py` 的信号逻辑、不动数据源模块；
7. 回测路径不受影响：回测（`scripts/signal_backtest.py` / run_chinext_timing 的回测分支）喂的是全量历史数据，正常路径金标准已覆盖，不得改动回测代码。
